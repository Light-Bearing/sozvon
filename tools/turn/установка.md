# Ретранслятор на своей машине

> **Проверено 16.09.2026** на RuVDS в Астане, Ubuntu 24.04, coturn 4.6.1.
> `turnutils_uclient`: адрес выделяется, 8 пакетов туда-обратно, потерь
> ноль. Снаружи STUN отвечает.

Ставится за несколько минут. Нужна машина с **публичным адресом прямо на
интерфейсе** — без всякого NAT перед ней.

## Что понадобится

- Ubuntu или Debian с публичным IPv4.
- Свободные порты: 3478 (UDP и TCP) и полторы тысячи портов для пересылки
  (49160–50659). Порт нужен не на разговор, а на каждое выделение места —
  у одного человека их бывает десятки.
- **Отдельно про 443.** Именно он проходит через зажатые сети — работу,
  гостиницу, кафе, — потому что неотличим от обычного сайта. Если 443
  занят чем-то другим, ретранслятор будет работать, но в самых глухих
  сетях не поможет. Это стоит решить отдельно.

## Установка

```
apt-get update && apt-get install -y coturn
```

Положить рядом `turnserver.conf`, подставив свой публичный адрес:

```
sed -i "s/ПОДСТАВИТЬ_ПУБЛИЧНЫЙ_АДРЕС/<адрес машины>/g" /etc/turnserver.conf
```

## Ключ

Ключ рождается **на самой машине** и никуда не уезжает — ни в переписку,
ни в репозиторий:

```
umask 077 && openssl rand -hex 32 > /etc/turnserver.secret
sed -i "s|^static-auth-secret=.*|static-auth-secret=$(cat /etc/turnserver.secret)|" /etc/turnserver.conf
chmod 600 /etc/turnserver.secret
chown root:turnserver /etc/turnserver.conf && chmod 640 /etc/turnserver.conf
```

**Конфиг — `640` и группа `turnserver`, не `600`.** Служба работает от
пользователя `turnserver` и читает конфиг от его имени. Закрой его
наглухо (`600`, только root) — и coturn молча стартует на настройках по
умолчанию: без пропусков (ретранслятор открыт всем), без запретов на
внутренние адреса, без квот, без журнала и с портами из всего диапазона
49152–65535, из которых брандмауэр пропускает лишь каждый десятый. Так и
было с 23.09 по 22.10.2026: ретранслятор «не сильно помогал» именно
поэтому.

Прочитать его, когда понадобится вписать в настройки «Созвона»:

```
cat /etc/turnserver.secret
```

## Запуск

```
sed -i "s/^#*TURNSERVER_ENABLED=.*/TURNSERVER_ENABLED=1/" /etc/default/coturn
ufw allow 3478/udp && ufw allow 3478/tcp && ufw allow 49160:50659/udp
systemctl enable --now coturn && systemctl status coturn --no-pager | head -5
```

## Проверка на самой машине

Считает короткий пропуск по ключу и пробует выделить адрес. Ключ при этом
остаётся в переменной и на экран не попадает:

```
S=$(cat /etc/turnserver.secret); U=$(( $(date +%s) + 3600 )):проверка
P=$(printf %s "$U" | openssl dgst -binary -sha1 -hmac "$S" | base64)
turnutils_uclient -u "$U" -w "$P" -p 3478 -n 2 -c <адрес машины> 2>&1 | tail -5
```

Строчка вида `total transmit ... received` без ошибок — ретранслятор жив
и пропуска считаются верно.

И обратное — **без пропуска должно быть отказано**. Если место выдаётся и
так, служба не прочитала конфиг (см. права выше):

```
sudo -u turnserver test -r /etc/turnserver.conf && echo "конфиг читается"
journalctl -u coturn -n 40 --no-pager | grep -E "realm|Listener address"
```

В журнале должны быть `Default realm: sozvon` и ваш адрес в
`Listener address`. Нет журнала вовсе — тот же признак.

## Настройка одной ссылкой — чтобы ничего не вписывать

Вместо того чтобы переносить адрес и ключ руками, сервер делает ссылку.
Открыли её один раз в своём браузере — и всё настроено навсегда.

```
printf '{"a":"%s","k":"%s"}' "<адрес машины>" "$(cat /etc/turnserver.secret)" \
  | base64 -w0 | tr '+/' '-_' | tr -d '=' \
  | sed 's|^|https://light-bearing.github.io/sozvon/#turn=|'
```

**Эту ссылку никому не пересылать** — в ней ключ целиком. Приложение
стирает её из адресной строки сразу, как прочитает, но в буфере обмена и
в переписке она останется.

Ссылка на сам разговор — совсем другая и ключа не содержит; её как раз
и посылают собеседникам.

## Как пропуска попадают к гостям

Ключ хранится **только у хозяина**, в его браузере, введённый один раз в
настройках. На каждый звонок браузер хозяина сам считает короткоживущий
пропуск (та же арифметика, что выше) и кладёт его в зашифрованное
рукопожатие. Гость получает бумажку на несколько часов и не видит ни
ключа, ни настроек — и по-прежнему нигде не регистрируется.
