# Стенд из двух трансляторов адресов

Домашнюю сеть не перенастроить под опыт, а без симметричного NAT проверить
приёмы обхода негде. Здесь оба вида трансляторов поднимаются в контейнерах.

```
peer-a ── router-a ──┐              ┌── router-b ── peer-b
(обычный домашний)   ├── net0 ──────┤   (симметричный)
                     │ «интернет»   │
                     └──── stun ────┘
```

```
docker compose up -d
docker exec nat-peer-a node /lab/peer.mjs a <ширина веера> [up|around]
docker exec nat-peer-b node /lab/peer.mjs b
```

Обе стороны работают **одним сокетом** от начала до конца: транслятор
запоминает отображение по внутреннему порту, и второй сокет проверял бы
не то, что задумано.

## Что стенд показал

**Топология с транзитом посередине обязательна.** Без промежуточного узла
пакеты с коротким сроком жизни умирать негде, и проверка выходит нечестной.

**Записи в трансляторе живут полминуты.** Между опытами таблицу надо
сбрасывать (`conntrack -F`), иначе прошлый веер отравляет следующий прогон.
Перезапускать контейнеры вместо сброса нельзя: у соседей остаётся старый
MAC, и связь пропадает вовсе.

### 1. Стена воспроизводится точно

А за обычным домашним NAT (порт снаружи один и тот же), Б за симметричным
(новый порт на каждого получателя). Б пишет А на известный адрес — пакет
выброшен: пришёл с порта, на который А не писал.

### 2. Пробивание дырки — это гонка, и проигравшего калечит

Даже когда оба за обычным NAT, исход зависит от того, чей пакет пришёл
первым. Выброшенный входящий пакет **всё равно заводит запись** в таблице
и занимает пару адресов. После этого собственный исходящий на тот же адрес
получает **другой внешний порт** — тот самый, которого собеседник не знает.

Замерено: А объявил порт 42610, Б туда стучал, а исходящие А уходили с
порта **8024**. Оба честно писали по правильным адресам — связи нет.

### 3. Веер на всё окно затыкает собеседника

Если обстрелять весь диапазон портов чужого транслятора, тот **не сможет
выделить порт для отправки**: все заняты нашими же записями. Замерено:
25 стуков вышли из peer-b, из router-b наружу — **ноль**.

### 4. Веер поуже выталкивает собеседника на непокрытое

Обратная сторона того же: занятые нами порты транслятор собеседника
обходит и выдаёт ему порт **из незанятого остатка** — то есть мимо веера.
Замерено дважды: веер 44926–45325, собеседник вышел с 45081 и с 45076.

### 5. Короткий срок жизни — верное лекарство, но браузеру недоступен

Пакет должен пройти свой транслятор и умереть по дороге, не добравшись до
чужого: своя запись есть, чужая таблица цела. В стенде связь этим поднять
пока не удалось (подозрение — ICMP «время истекло» рвёт собственные записи),
и разобраться стоит. Но главное известно заранее: **в браузере срок жизни
пакета не задать.** Это рычаг родного приложения.

## Вывод на сегодня

Угадывание портов из вкладки **не работает** — и не по случайности, а по
устройству: любой наш разведывательный пакет портит ровно то отображение,
ради которого посылался. Чтобы не портил, нужен короткий срок жизни, а его
даёт только родное приложение.
